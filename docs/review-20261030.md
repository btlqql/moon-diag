# MoonDiag：多ECU诊断日志与下载过程离线审计工具

账号：btlqql。主要语言：MoonBit。许可：Apache-2.0。修订日期：2026-10-30。

## 对审核意见的直接回应

本项目认可基础ISO-TP、UDS、DTC解析已有实现，不以这些协议名称或生态唯一性作为增量价值。当前可演示的增量是：将分散报文还原为**按ECU隔离的诊断状态及下载过程约束**，定位“报文各自可解码，但请求与响应、权限或传输顺序不一致”的问题。

## 典型应用场景

**诊断台架回归：** 同一CAN日志中两个ECU交错通信，一个完成seed请求，另一个直接发送key。工具按物理请求ID分别维护状态，第二个ECU不会借用第一个的seed而被判断为已解锁。只有收到匹配的成功key响应才记录解锁；拒绝响应不会产生解锁状态。

**固件下载日志排错：** 工程师拿到RequestDownload→TransferData→RequestTransferExit日志，工具读取memorySize和ECU协商的块大小，检查块计数、应答回显及最终确认字节数，定位漏块、错误重试、超长块和提前结束。它审计已有传输，不执行真实刷写。

**DID回归核对：** 0x22请求与0x62响应服务号匹配仍不足以证明内容对应。对于单DID请求，工具进一步检查DID回显，避免把另一个标识符的数据计为正确响应。

## 本轮实际完成

- 新增`analyze_uds_network`与逐ECU报告；默认0x7E0–0x7E7请求对应0x7E8–0x7EF响应，各自拥有待响应队列、会话和安全访问状态。
- 修复发送key就提前解锁；seed只由成功响应确认，检查子功能回显；成功切换会话后清除旧安全状态。
- 新增0x34／0x36／0x37下载审计：地址／大小格式、协商块长、块计数FF→00回绕、确认字节累计、相同已确认块重传去重、总量超限、退出时大小不符及未完成下载。
- 保留ISO-TP重组、pending、负响应、缺失响应及OBD/DTC解码；CLI发现fail返回退出码1。

## 可复现案例

```sh
moon run cmd/main --target js -- session examples/uds-sessions/download-ok.log
moon run cmd/main --target js -- session examples/uds-sessions/download-size-mismatch.log
moon run cmd/main --target js -- session examples/uds-sessions/cross-ecu-security.log
```

实际结果：第一例pass，确认4字节／退出0；第二例`TRANSFER_SIZE_MISMATCH`／退出1；第三例第二个ECU报告`SECURITY_SEQUENCE`、安全级别仍为0／退出1。全部是作者构造的回归样例，不是真实车辆或客户现场验证。

## 当前实现边界

只分析离线经典CAN日志，不进行实际刷写或OEM密钥计算。物理寻址映射为上述固定范围；其他ID按同ID关联，未支持可配置映射、功能寻址广播、多接口隔离、DoIP、CAN FD或完整UDS服务矩阵。下载审计只覆盖未压缩、未加密的dataFormatIdentifier=0场景；不把传输字节等同于固件真实性或可启动性。未验证真实车辆日志、P2/P2*超时、STmin、ISO-TP流控时序或硬件。基础协议复用的工程改造与真实用户采用效果未作证明。
